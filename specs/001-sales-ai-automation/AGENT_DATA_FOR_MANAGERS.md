# Agent 1-6 数据输出整理：业务主管视图

**文档目的**：说明 AI 分析系统从每个销售案件中提取的关键数据，以及如何为业务主管提供决策支持。

**最后更新**：2025-11-03

---

## 📊 数据流程概览

```
音檔 → 转录 + 说话者识别 → Agent 1-6 分析 → 结构化数据存入 Firestore → Agent 8 汇总 → 主管报告
```

**每个案件处理后，系统会产生以下 6 大维度的销售分析数据**：

---

## 🎯 Agent 1: 参与者分析（Participant Profile）

### 输出数据

| 数据项 | 说明 | 示例 | 主管价值 ⭐ |
|--------|------|------|------------|
| **参与者角色** | 识别每个说话者的身份 | "老板/决策者"、"店长/使用者"、"财务主管" | ⭐⭐⭐ 判断是否接触到关键决策者 |
| **决策权力分数** | 0-100，评估决策影响力 | 90（老板）、60（店长） | ⭐⭐⭐ 评估案件质量 |
| **影响力级别** | 主要/次要/观察者 | "primary"、"secondary" | ⭐⭐ 了解决策结构 |
| **人格类型** | DISC 风格分析 | "driver"（结果导向）、"analytical"（数据导向） | ⭐⭐ 指导沟通策略 |
| **关注点** | 客户最在意的问题 | ["成本控制", "人力短缺", "营运效率"] | ⭐⭐⭐ 产品定位参考 |
| **说话时长占比** | 各参与者发言比例 | 老板 65%、店长 30%、其他 5% | ⭐ 会议主导性判断 |

### 主管应用场景

✅ **案件质量评估**：是否接触到真正的决策者？
✅ **风险预警**：若决策权力最高者未参与，成交风险高
✅ **团队培训**：发现业务在识别关键人物方面的能力差异

---

## 💭 Agent 2: 情绪与态度分析（Sentiment & Attitude）

### 输出数据

| 数据项 | 说明 | 示例 | 主管价值 ⭐ |
|--------|------|------|------------|
| **整体情绪** | positive/neutral/negative | "positive" + 置信度 85% | ⭐⭐⭐ 快速判断案件状态 |
| **信任度** | 对业务/品牌的信任（0-100） | 78 | ⭐⭐⭐ 客户关系健康度 |
| **参与度** | 客户投入程度（0-100） | 82 | ⭐⭐ 成交意愿指标 |
| **技术接受度** | 对新系统的开放程度（0-100） | 65 | ⭐⭐ 导入难度预判 |
| **购买信号** | 明确的成交意向 | ["想尽快上线", "预算已准备好"] + 时间戳 | ⭐⭐⭐ 优先跟进依据 |
| **反对信号** | 障碍或疑虑 | ["担心员工不会用", "价格偏高"] + 严重度 | ⭐⭐⭐ 风险识别 |
| **情绪曲线** | 对话过程中的情绪变化 | 0-10min: positive → 10-25min: neutral → 25-40min: negative | ⭐⭐ 沟通效果诊断 |

### 主管应用场景

✅ **优先级排序**：高信任度 + 强购买信号 = 优先跟进
✅ **风险干预**：低信任度 + 严重反对信号 = 需主管介入
✅ **业务辅导**：情绪曲线下降 = 检讨沟通策略

---

## 🎁 Agent 3: 产品需求提取（Product Needs）

### 输出数据

| 数据项 | 说明 | 示例 | 主管价值 ⭐ |
|--------|------|------|------------|
| **明确需求** | 客户直接表达的需求 | "需要掃碼點餐功能" + 引用原文 | ⭐⭐⭐ 产品推荐依据 |
| **隐含需求** | 从痛点推断的潜在需求 | "提到尖峰时段人手不足" → 推断需要"自助点餐" | ⭐⭐⭐ 交叉销售机会 |
| **推荐产品** | AI 建议的产品组合 | "POS 基础版 + 线上订位" + 匹配度评分 | ⭐⭐ 方案参考 |
| **预算估计** | 客户预算范围 | 最低 $30K ~ 最高 $50K，灵活性：中等 | ⭐⭐⭐ 定价策略 |
| **支付偏好** | 付款方式倾向 | "分期付款"、"订阅制" | ⭐⭐ 金融方案设计 |
| **决策时间线** | 紧急度与预期决策日 | "within_month"，驾驶因素："旧系统合约到期" | ⭐⭐⭐ 跟进节奏规划 |
| **价格敏感度** | 对价格的在意程度 | "high"（曾提及竞品价格） | ⭐⭐ 折扣策略参考 |

### 主管应用场景

✅ **报价审核**：业务提出的方案是否符合客户需求？
✅ **交叉销售**：发现隐含需求，扩大客单价
✅ **管线管理**：根据决策时间线预测本月/本季成交概率

---

## 🏆 Agent 4: 竞品情报分析（Competitor Intelligence）

### 输出数据

| 数据项 | 说明 | 示例 | 主管价值 ⭐ |
|--------|------|------|------------|
| **提及的竞品** | 客户讨论过的竞品 | "Eats365"、"Foodpanda POS" | ⭐⭐⭐ 竞争态势监控 |
| **客户满意度** | 对竞品的评价（0-100） | Eats365: 60分（便宜但功能不足） | ⭐⭐⭐ 竞品弱点情报 |
| **关系状态** | 与竞品的关系 | "past_user"（曾使用）、"evaluating"（评估中） | ⭐⭐⭐ 转换难度判断 |
| **我们的优势** | 基于客户痛点的优势点 | ["庫存管理功能更強", "客服響應更快"] | ⭐⭐ 话术武器库 |
| **获胜策略** | AI 建议的竞争策略 | "強調長期 ROI，避免價格戰" | ⭐⭐ 战术参考 |
| **转化概率** | 从竞品转换的可能性（0-100） | 75%（高意愿） | ⭐⭐ 资源投入决策 |

### 主管应用场景

✅ **竞争情报库**：哪些竞品最常出现？客户如何评价？
✅ **产品改进**：客户提到的竞品优势是否值得学习？
✅ **战术指导**：针对特定竞品的应对策略培训

---

## 📋 Agent 5: 功能需求问卷（Discovery Questionnaire）

### 输出数据

针对 **22 个具体功能**（分 6 大类），自动提取结构化的需求信息：

#### 功能分类
1. **点餐与订单管理**：扫码点餐、多人扫码、套餐加价购、智能推荐、POS点餐、线上接单
2. **线上整合服务**：线上订位、线上外带、云端餐厅、Google/LINE整合、外送平台整合
3. **成本与库存**：成本控管、库存管理、帐款管理
4. **业绩与分析**：销售分析、报表生成
5. **客户关系**：零秒集点、会员管理
6. **企业级功能**：总部系统、连锁管理

#### 每个功能的数据结构

| 数据项 | 说明 | 示例 | 主管价值 ⭐ |
|--------|------|------|------------|
| **当前状态** | 是否使用该功能 | "未使用"、"使用中"、"考虑中" | ⭐⭐⭐ 销售机会识别 |
| **需求判断** | 是否有需求 | true / false / null（未明确） | ⭐⭐⭐ 产品组合决策 |
| **需求原因** | 为什么需要 | "人手不足，希望客人自助點餐" + 置信度 85% + 引用原文 | ⭐⭐ 价值主张定制 |
| **不需求原因** | 为什么不需要 | "客人都是老人家不會用" + 置信度 90% | ⭐⭐⭐ 风险识别 |
| **感知价值** | 对功能的价值评估（0-100） | 75分，正面："省人力"，负面："擔心客人不會用" | ⭐⭐ 功能推广策略 |
| **实施意愿** | 导入意愿度 | "medium"（中等） | ⭐⭐⭐ 成交概率 |
| **障碍因素** | 导入障碍 | [{"type": "budget", "severity": "high", "detail": "月費太貴"}] | ⭐⭐⭐ 需解决的问题 |
| **考虑时间线** | 决策紧急度 | "3-6個月內"，urgency: "low" | ⭐⭐ 跟进节奏 |
| **完整度评分** | 问卷回答完整度（0-100） | 80%（大部分问题都讨论到） | ⭐ 需补充的信息 |

### 主管应用场景

✅ **产品需求热度分析**：哪些功能最常被讨论？哪些被忽略？
✅ **障碍因素统计**：团队最常遇到的客户顾虑是什么？（如：预算、技术接受度）
✅ **功能推广策略**：感知价值低的功能需要更好的 demo 或案例
✅ **客单价优化**：识别交叉销售机会（客户讨论多个功能）

## 🎓 Agent 6: 销售教练合成（Sales Coach）

### 输出数据（整合前面 5 个 Agent 的结果）

| 数据项 | 说明 | 示例 | 主管价值 ⭐ |
|--------|------|------|------------|
| **关键决策者** | 最重要的决策人物 | "老闆娘（財務決策者）" + 主要关注点 | ⭐⭐⭐ 高层介入判断 |
| **交易健康度** | 成交可能性评分（0-100） | 78分，sentiment: positive，reasoning: "預算充足且決策者參與" | ⭐⭐⭐⭐⭐ **核心 KPI** |
| **推荐产品组合** | 完整方案建议 | "POS 基礎版 + 線上訂位 + 掃碼點餐" + 总价 $45K | ⭐⭐ 方案检核 |
| **定价策略** | 建议的报价策略 | "強調 ROI，提供 12 期分期，首年折扣 10%" | ⭐⭐ 定价审批参考 |
| **竞争定位** | 针对竞品的策略 | "避免與 Eats365 比價，強調長期價值與服務" | ⭐⭐ 竞争应对 |
| **销售阶段** | 当前阶段分类 | "需要證明型"（需要 demo/案例） | ⭐⭐⭐ 资源配置 |
| **最大风险** | 最可能失败的原因 | "預算限制可能導致只採購 POS 基礎版" + 缓解策略 | ⭐⭐⭐⭐ **风险管理** |
| **下一步行动** | 3 个优先行动项 | 1. "安排產品示範"（48小時內，优先级 1）<br>2. "準備 ROI 試算表"（本週內，优先级 2） | ⭐⭐⭐ 执行指导 |
| **话术建议** | 针对性的沟通话术 | "如果客戶提及預算，回應：'我們可以提供分期方案...'" | ⭐⭐ 业务培训 |
| **业务表现反馈** | 对业务的评价 | 优势：["需求挖掘深入", "建立良好信任"]<br>改进：["結案速度較慢"] | ⭐⭐⭐ **绩效辅导** |

### 主管应用场景

✅ **案件健康度仪表板**：一目了然哪些案件需要关注
✅ **主管介入决策**：健康度 <60 的案件，主管应该介入
✅ **业务辅导**：根据"业务表现反馈"进行针对性指导
✅ **预测管线**：根据销售阶段预测本月/本季成交金额

## 🎯 Agent 8: 业务主管报告（即将实现）

### 汇总所有案件数据，产出管理报告

#### 输出内容

1. **团队整体绩效**
   - 总案件数、完成率、平均健康度、平均处理时间

2. **个人业务排名**
   - 每位业务的案件数、平均健康度、完成率
   - 个人优势识别、改进建议

3. **需要关注的案件**
   - 健康度 <60 的案件列表
   - 风险原因 + 建议的介入措施

4. **团队洞察**
   - 共同挑战（例如：60% 案件提及预算限制）
   - 成功模式（例如：强调库存管理功能的案件成交率高）
   - 培训需求（例如：价值销售训练）

5. **竞品情报汇总**
   - 最常出现的竞品及客户评价
   - 应对策略建议

6. **产品需求热度**
   - 哪些功能最常被讨论？
   - 哪些障碍因素最常出现？

#### 发送方式
- **每日报告**：每天早上 9:00 发送到 Slack `#sales-ai-monitor` 频道
- **周报**：每周一汇总过去 7 天数据
- **按需报告**：主管可通过 `/team-report` 命令随时请求

## 📈 数据价值矩阵

为业务主管提供决策支持的关键指标：

| 决策场景 | 关键数据来源 | 数据项 |
|---------|------------|-------|
| **案件优先级排序** | Agent 2 + Agent 6 | 信任度、购买信号、交易健康度 |
| **主管介入判断** | Agent 6 | 健康度 <60、最大风险、决策者参与度 |
| **报价审批** | Agent 3 + Agent 6 | 预算估计、推荐产品组合、定价策略 |
| **业务辅导** | Agent 6 | 业务表现反馈（优势/劣势） |
| **竞争策略制定** | Agent 4 | 竞品提及频率、客户满意度、获胜策略 |
| **产品策略调整** | Agent 5 + Agent 8 | 功能需求热度、障碍因素统计 |
| **培训需求识别** | Agent 1 + Agent 2 + Agent 8 | 决策者识别准确率、情绪管理、团队共同挑战 |
| **管线预测** | Agent 3 + Agent 6 | 决策时间线、销售阶段、交易健康度 |

## 🔒 数据访问权限

### 业务人员
- ✅ 查看自己负责的案件的所有 Agent 1-6 分析
- ❌ 无法查看其他业务的案件
- ❌ 无法查看 Agent 8 团队报告

### 业务主管
- ✅ 查看所有案件的所有 Agent 1-6 分析
- ✅ 查看 Agent 8 团队报告
- ✅ 查看业务绩效排名
- ✅ 通过 Slack 接收每日/每周报告
- ✅ 通过 Firestore/Sheets 导出原始数据

### 系统管理员
- ✅ 完整数据访问权限
- ✅ Agent prompt 调整
- ✅ 系统效能监控

## 💡 数据应用最佳实践

### 每日例行（9:00-9:30）
1. 查看 Agent 8 每日报告（Slack 自动推送）
2. 关注"需要关注的案件"清单
3. 对健康度 <60 的案件安排主管介入

### 每周复盘（周一早会）
1. 查看 Agent 8 周报
2. 与业务讨论"改进建议"
3. 根据"团队洞察"安排培训

### 每月战略会议
1. 分析竞品情报趋势
2. 审视产品需求热度变化
3. 调整销售策略与资源配置
