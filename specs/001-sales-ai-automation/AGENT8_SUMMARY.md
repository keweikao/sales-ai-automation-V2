## 🏗️ 系统架构

### 核心原则：**复用现有 Slack App 和基础设施**

```
┌─────────────────────────────────────────┐
│         现有 Slack App                   │
│         (Sales AI Bot)                  │
└─────────────────┬───────────────────────┘
                  │
        ┌─────────┴─────────┐
        │                   │
        ▼                   ▼
┌───────────────┐    ┌──────────────┐
│ slack-service │    │ Cloud        │
│ (现有)        │    │ Function     │
│               │    │ (新建)       │
│ + Agent 8     │    │              │
│   对话交互    │    │ Agent 8      │
│   🆕          │    │ 定时报告     │
└───────────────┘    └──────────────┘
        │                   │
        └─────────┬─────────┘
                  │
                  ▼
        ┌─────────────────┐
        │   Firestore     │
        │   (Agent 1-6    │
        │    数据)        │
        └─────────────────┘
```

**关键点**：
- ✅ **同一个 Slack App**：复用现有 Bot Token 和配置
- ✅ **对话功能**：添加到现有 `slack-service`
- ✅ **定时报告**：使用轻量级 Cloud Function
- ✅ **数据来源**：都从 Firestore 读取 Agent 1-6 的分析结果

## 📊 Agent 8 的数据来源

Agent 8 **不会重复分析**，而是从 Firestore 读取 Agent 1-6 已经分析好的结构化数据：

| Agent | 提供的数据 | Agent 8 如何使用 |
|-------|-----------|-----------------|
| **Agent 1** | 参与者角色、决策权力 | 判断是否接触到关键决策者 |
| **Agent 2** | 情绪、信任度、购买信号 | 评估案件状态和优先级 |
| **Agent 3** | 需求、预算、时间线 | 预测管线和成交时间 |
| **Agent 4** | 竞品、客户评价 | 竞争策略分析 |
| **Agent 5** | 22 个功能的需求分析 | 产品需求热度统计 |
| **Agent 6** | **健康度**、风险、下一步 | **核心 KPI**，主管介入依据 |

Agent 8 的工作：**汇总 + 洞察 + 建议**

## 💬 两种使用方式

### 方式 1：对话式（随时提问）

```
主管: /ask-agent8 王小明本週表現如何？

Bot: 王小明本週完成 5 件案件，平均健康度 82 分 🥇

📊 量化指標
• 案件數：5 件（團隊第一）
• 客戶信任度：85

💪 主要優勢
• 需求挖掘深入
• 客戶關係良好

📈 改進建議
• 結案速度偏慢（5天 vs 團隊3天）

💡 你可能還想知道：
• 他的優先案件是什麼？
• 如何幫助他提升結案速度？
```

**支持的 6 大类问题**：
1. 团队整体表现
2. 个人业务绩效
3. 案件详细分析
4. 竞品情报
5. 产品需求洞察
6. 趋势对比

## ❓ 常见问题

### Q1: 对话式 Agent 8 和定时报告有什么区别？

**对话式**：主管**主动询问**，立即得到答案
**定时报告**：系统**自动推送**，固定格式

**建议**：优先实现对话式，因为更灵活、价值更高

---

### Q2: 需要新建 Slack App 吗？

**不需要**！复用现有的 Sales AI Bot，只需：
1. 添加新的 `/ask-agent8` 命令
2. 在 `slack-service` 中添加代码

---

### Q3: Agent 8 会重复分析数据吗？

**不会**！Agent 8 从 Firestore 读取 Agent 1-6 已经分析好的结构化数据，只做：
- 汇总（多个案件的数据）
- 洞察（发现模式和趋势）
- 建议（可操作的行动项）

---

### Q4: 主管权限如何管理？

两种方式：
1. **硬编码**：在代码中维护主管 Slack ID 列表
2. **Firestore**：在 `users` collection 中添加 `role` 字段

建议使用 Firestore，更灵活。

---

先做对话式，因为：
